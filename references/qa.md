# 交付前检查清单

按顺序做，每一项都要有实际证据（命令输出或看过的画面），不能凭"应该没问题"。

## 1. 规划阶段（写完 edit.json 后）
- [ ] `python dms.py lint edit.json` 没有硬错误；建议项逐条看过（压字幕、贴边、过密、人物窗变化太快、文案过长）。
- [ ] 每一段的大字/数字/结论都来自口播原话，没有替博主编造观点；示意界面标了"界面示意"。
- [ ] 所有 `cue` 都解析到了（build 时没有"关键词没找到"的提示）。
- [ ] 人物窗：每次形态变化都有理由（让位给内容 / 拉近观众 / 收尾）；没有真人画面的区间是 `hidden`。

- [ ] `python dms.py direct 工程`（导演检查）合计 0 处建议；确实不适用的建议，在交付说明里写理由。
- [ ] 分镜草稿里的 `draft: true` 和括号占位文案全部处理掉了。
- [ ] 转场：常规转场 2–3 种为主；`morph` 两侧有同名 `share`；`text-mask` 那一刻人物不是全屏。

## 2. 画面（build 后）
- [ ] `python dms.py stills 工程 时间点…`：至少覆盖 首帧、每段转场前/中/后、每个砸字/印章落定、最长一行文字、片尾。
- [ ] 小圆窗里看得到双眼、嘴巴、下巴；全屏人物没被裁掉头顶和手势。
- [ ] 文字没有溢出、没有互相压住、没有压到人脸和字幕区。
- [ ] 同一话题的段落共用环境（墙/底色），没有"每句一张新卡"。
- [ ] 浏览器打开工程 `index.html`，拖动时间轴看几个复杂动作的连续过程（不能只看静帧）。
- [ ] 遮罩类转场（wipe-diag / split / rect / blinds / text-mask）的中间帧：旧元素没有压在新背景上；`morph` 中间帧：承接对象清晰、没有回跳。
- [ ] 字幕关键词在说到的那一刻才变色，长句按词断行（不把一个词拆成两行）。

## 3. 声音（audio 后）
- [ ] 混音响度在 −16 ~ −14 LUFS，真峰值 ≤ −1 dBTP（audio 命令会打印）。
- [ ] 音效数量合理（每秒不超过 1.2 个），没有连成一片的提示音。
- [ ] 默认不加背景音乐；用户要求配乐时，配乐情绪与内容一致、说话时让位。助手听不到声音时要明确告诉用户"请试听确认"。

## 4. 成片（render 后）
- [ ] `check` 输出：分辨率、帧率、时长与工程一致，完整解码通过。
- [ ] 抽查成片 MP4 的帧（不是工程静帧）：字幕烧录正确、字体是中文黑体而不是方框。
- [ ] `export` 打包：成片、无字幕画面、SRT/ASS、分轨、Premiere/达芬奇 XML、HTML 动画工程都在 deliver/ 里。

## 5. 交付说明里写清楚
- 剪掉了哪些部分（口误、停顿、重复），原片其余部分原样保留。
- 字幕里纠正了哪些识别错误。
- 哪些检查做过（静帧 / 连续片段 / 完整解码 / 响度），哪些需要用户自己看听确认。
