# 编排手册（给所有助手：Claude / Codex / 豆包 / WorkBuddy / CodeBuddy …）

技能只提供积木：引擎组件、动效库、328 张原卡，以及已安装的行业模板包。**成片好不好，九成取决于编排和看图修改**：每一段放什么、放在哪、什么时候出现、出来以后好不好看。积木怎么动是写死在代码里的，谁调用都一样，差距全在编排。这份手册把编排拆成固定步骤，照做就不会剪成"除了字幕就是字幕"。

## 0. 硬指标（导演检查 `dms.py direct` 会逐条查；不达标不渲染）

| 指标 | 要求 |
|---|---|
| 动效数量 | **每分钟至少 15–20 个**（每个非背景层、每个 demo-zone 拍都算一个；每段 2–4 层：主画面 + 强调 + 辅助） |
| 换画面频率 | **一两句话换一次画面，4–10 秒一屏**；一段超过 12 秒，段内必须翻页（`out` + 新元素、demo-zone 换拍、窗口推到新位置），否则拆段 |
| 主画面 | 每段至少一个**非文字**主画面；只有大字 / 胶囊的段落不超过 1/4，超过 3 秒的纯文字段一律要改 |
| 不千篇一律 | 同一个组件不超过 35% 的段落；自制动效一条片子最多用 3 段；画面组件种类 ≥ max(5, 段数 / 3) |
| 背景 | **每分钟 2–3 种背景**，全片至少 max(4, 分钟数 × 2.5) 种；同一背景连续不超过 20 秒。文字墙要换皮肤、换颜色（见第 5 节背景菜单） |
| 看得清 | 主画面占画面 30–60%；1080p 下大字 ≥ 80px、正文 ≥ 28px；前景和背景对比鲜明（浅底深字 / 深底浅字） |
| 真实 | 大字、数字、结论只来自口播原话；示意界面标"界面示意"；原卡里的样板文字必须全部换成本期内容 |

**底线一句话：画面要证明口播，不是复述口播。** 字幕已经在说"说了什么"，画面要让观众看到那个东西：数字跳出来、两个方案摆在一起比、步骤一格格点亮、界面里被点中的地方放大、比喻变成一个会动的物件。

## 1. 先看懂素材

把母版抽成缩略图，一张张看：哪些区间有真人、在画面哪里；录屏在演示什么、重点在画面哪个位置。

```bash
ffmpeg -i work/master.mp4 -vf "fps=1/5,scale=384:-1,tile=6x5" -frames:v 3 work/sheet_%d.jpg   # 每 5 秒一格
```

录屏要放大到某处时，截一帧叠上 10×10 网格量坐标，写进 `window.zoom` / `callouts` / `cursor`。

## 2. 先写编排单，再写 edit.json

`dms.py scaffold` 切好段落后，**按"一两句话一段"重新切**，然后每段填一行：

| 段 | 口播原话（摘要） | 这句在说什么（对象 · 关系 · 动作 · 结果） | 观众该看到什么（一句话画面） | 主画面 | 强调（落在哪个字） | 辅助 | 背景 | 人物 | 转场 |
|---|---|---|---|---|---|---|---|---|---|

范例（《Claude vs Codex 动画实测》，完整工程在 `examples/claude-vs-codex/`，28 段，每分钟约 20 个动效，背景 16 种）：

| 段 | 口播 | 在说什么 | 观众该看到 | 主画面 | 强调 | 辅助 | 背景 | 转场 |
|---|---|---|---|---|---|---|---|---|
| s04 | 模型是 Opus 5.5，推理强度中等 | 测试条件 | 录屏推到模型菜单，"Medium"被框出来 | `window`（zoom + highlight） | — | 胶囊「Opus 5.5」「中等」逐个点亮 | 铂金文字墙 | morph |
| s06 | 逻辑、物理、动效合理性都符合，美观差点 | 逐项打分 | 动画在跑，右边清单一条条打勾，最后一条亮黄色警告 | `window` + `checklist` | 胶带「挑不出毛病」 | — | 墨玉文字墙 `wall-jade` | morph |
| s07 | 推理强度变成高，效果完全不一样 | 条件变 → 结果变 | "中等"被划掉改成"高"，分割线扫过，白天变日落 | `strike` → `fx-before-after` | 说到"完全不一样"揭晓 | 胶囊「同一句提示词」 | 霓虹紫 `d-neon` | wipe-diag |
| s14 | 改个小问题三十分钟起步 | 等很久 | 进度条卡在 12% → 巨号「30 分钟起步」 | `progress` → `number` | 气泡"都经历过吧" | — | 曜石文字墙 `wall-obsidian` | push-left |
| s17 | 注意 KYC，护照 + 人脸过了 | 风险 + 步骤 | 「注意」印章砸下 → 右边流程一步步点亮 | `stamp` → `flow` | 「2–3 个账号」 | 胶囊「中转很稳定」 | 红色放射 `a-red` | wipe-diag |

写完先自问：
- 关掉字幕，只看画面，能看懂吗？
- 相邻几段是不是长得一样？
- 每分钟的动效够 15 个吗？
- 背景换了几种？

## 3. 选动效：先用现成的（组件、动效库、原卡都能用），再现做

1. **按语义查目录** `references/catalog.md`：01 开场 / 02 数字 / 03 对比 / 04 流程 / 05 对话 / 09 界面 / 11 卡片标注 / 12 质感。
2. **按关键词搜**：`dms.py catalog 价格`、`dms.py catalog 等待 断线`、`dms.py catalog 对比 成本`。结果里有每一项的写法，可以直接抄。
3. **原卡（328 张）可以直接改来用**（原卡库文件 `assets/dayan-library.html` 不随公开仓库分发，需自行放入；没有时跳过这一项）。 原卡里的文字、数字、价格、产品名都是样板，按本期口播换掉即可：
   ```bash
   dms.py card M03·2                       # 样张（入场 / 落定 / 后段）+ 列出卡里全部可见文字 + 写法
   ```
   ```json
   {"c": "dayan", "cue": "五分之一", "lead": -0.3, "box": "full",
    "props": {"id": "M03·2", "replace": [["全部办下来只要", "GPT-6.1 Sol 的成本只要"], ["¥8,000", "1/5"], [".00", ""],
                                          ["汇率 1 : 1", "对比 GPT-6 Astra"], ["¥17,378", "省 80%"],
                                          ["那香港哪家最便宜", "日常任务交给 Codex"], ["So which one in Hong Kong is cheapest", "CODEX · COST"]]}}
   ```
   - `replace` 是 [原文, 新文] 的列表，`dms.py card` 列出的每一条可见文字都要换掉，不需要的换成空字符串 `""`。
   - 换完再跑 `dms.py card M03·2 --replace 替换表.json` 看样张，确认没有残留的样板价格、别家产品名、别人的标题。
   - 原卡里的文字墙和署名自动换成 edit.json 的 brand。原卡是 1920×1080 横屏版式：横屏全屏用最好；4:3 / 竖屏放进 `box` 小框里会缩小，先看样张。
   - 原卡适合做"一屏一个重点"的整屏画面（数字砸入、价格卡、对比卡、清单、开场翻牌、下期预告……），和组件交替使用，画面样式会丰富很多。
4. **引擎组件和动效库**：能按关键词对齐每个子元素、自带音效、三种画幅自适应。需要"说到哪个字哪个元素出来"的段落优先用它们。
5. **行业包模板**（`template list`，edit.json 写了 `packs` 时）：语义匹配到的段落优先用包里的模板，写 `"template": "<包名>:<模板 id>"` 和 `slots`；规范见 motion-templates.md。

## 4. 现做新动效（目录里没有贴切的，就做"这一句专属"的）

- **画的是这句话里的那个东西**：讲"思考中、断线"，就做一个加载圈转着转着断开；讲"命中缓存成本变低"，就让价格条被缓存图标吃掉一截。**不要做通用的"深色面板 + 几行灰字"**，那种东西放哪段都一样，三次就腻。
- **先读参考实现**：
  - `effects/fx-before-after/`：最简单；
  - `effects/fx-word-tape/`：状态推进；
  - `effects/fx-storyboard/`：一个动效里演四种小画面；
  - `effects/fx-editor-timeline/`：光标按口播点中、当场改内容。
  也可以用 `dms.py card <卡号>` 看原卡的版式和动作，照着做成可按关键词对齐的新动效。
- **写法**：`dms.py effect new fx-名字 --name 中文名 --use "说到什么时用"`，然后写 `component.js`：
  - `build`：只建一次 DOM；
  - `update(el, lt, props)`：只用时间算状态；
  - `sfx`：每个接触点配一个音效。
- **至少 3 个状态变化**卡在口播的字上；要有入场和落定，退场要有方向；尺寸用 `cqw` / `cqh`。
- **检查**：`dms.py effect check fx-名字` 出三画幅样张，打开看。通过后自动沉淀进 `effects/`，下次直接用。
- 同一个自制动效一条片子最多用 3 段。

## 5. 段落配方和背景菜单

**段落配方**：每段 2–4 层。下表的组件都能换成目录里同类的原卡。

| 段落类型 | 主画面 | 强调 | 辅助 |
|---|---|---|---|
| 数字 / 价格 / 倍数 | `number` 巨号滚动，或原卡 M03 / P04 系列 | `stamp` / `burst` | 对比 `bars`，或一句胶囊 |
| A vs B | `compare`（胜者揭晓）或 `fx-before-after` | 揭晓时 `stamp` | 两侧标签 `chips` |
| 步骤 / 操作 | `flow`（每步 cue）/ `checklist` | 最后一步高亮 | `progress` 走满 |
| 等待 / 执行中 | `progress`（卡住不动）/ 原卡进度类 | 卡住时的气泡 / 印章 | 数字跳出时长 |
| 录屏 / 软件 | `window`（zoom 推近 + highlight 框 + cursor 点击 + callouts 便签） | 说到的那处放大 | 右侧胶囊 / 小标题 |
| 观点 / 情绪爆点 | `title` slam + `burst` | `stamp` / `confetti` | 贴纸 `sticker` |
| 我问它 / 它回答 | `chat` / `type` | 关键回复高亮 | — |
| 功能 / 优势 | 人物侧推 + `demo-zone` 每拍换演示（`panel-stack` / `chat` / `number`…） | `glow-quote` 结论 | — |
| 风险 / 提醒 | `stamp`「注意」+ `flow` | 红色背景 | 数字 |
| 结尾 | `fx-cta-buttons` → `namecard` | 红色放射背景 | — |

**背景菜单**（写在场景的 `look` 上，每分钟换 2–3 种，同一个话题内可以共用）：

| 类型 | look |
|---|---|
| 色块 | `a-blue` 纯蓝 · `a-violet` 紫 · `a-lime` 荧光绿 · `a-red` 红色放射 |
| 质感 | `b-film` 暗胶片 · `b-paper` 米白纸 · `d-neon` 霓虹紫 + 水印 · `d-hud` HUD 暗蓝 · `a-thumbs` 作品墙 |
| 品牌文字墙（16 套皮肤，颜色和字体都不同） | `wall-pop` 潮玩撞色 · `wall-gold` 香槟黑金 · `wall-acid` 电子酸性 · `wall-song` 宋式绢本 · `wall-chrome` 银盐霓虹 · `wall-lime` 荧光黄绿 · `wall-obsidian` 曜石鎏金 · `wall-platinum` 雾面铂金 · `wall-abyss` 深海黄铜 · `wall-hollow` 玄青描边 · `wall-satin` 缎面香槟 · `wall-lacquer` 朱漆描金 · `wall-frost` 霜银星尘 · `wall-porcelain` 素瓷月白 · `wall-jade` 墨玉叠金 · `wall-mist` 雾霭灰紫 |

- 亮底款文字墙写 `{"name": "wall-porcelain", "light": true}`。
- 想要更特别的背景，也可以用原卡的整屏画面（原卡自带背景），或 `bg-burst` / `bg-grid` / `bg-glow` 组合。

## 6. 看图检查（必须做）

```bash
dms.py build edit.json proj
dms.py plan proj                # 编排单：每段的主画面；"⚠ 只有文字"的段落必须改
dms.py stills proj 3,11,19,…    # 每 8–10 秒一帧，外加转场前、中、后
dms.py direct proj              # 导演检查 8 类：动效数量、换画面频率、背景种类、千篇一律、只有文字……
dms.py sweep proj
```

看接触表时逐张问：
- 主体够大吗？字读得清吗？
- 和上一张长得一样吗？
- 有没有压脸、压字幕？前景和背景的对比够不够？
- 原卡里还有没有没换掉的样板字？

导演检查要做到 0 条建议，确实不适用的在交付时写明理由。

## 7. 常见失败（一次外部助手剪辑样本的复盘，180 秒、19 段）

- 19 段里 15 段是"左上角小标题 + 同一个深色界面示意卡"，换的只是卡里几行灰字。
- 主画面只有 5 种；动效库 16 个只用了 1 个；328 张原卡一张没用。
- 每分钟 13 个动效，背景 4 种，三段超过 13 秒没换画面。
- 界面示意卡里的字太小，手机上看不清。
- 旧版导演检查不查这些，所以显示 0 条建议。现在会报 9 条。
- 用的是旧版技能 1.7.0。请始终用最新版。

## 8. 给不同助手

- **Codex**：会读技能根目录的 `AGENTS.md`。
- **豆包 / WorkBuddy / CodeBuddy**：在对话里说"先读 <技能目录>/SKILL.md 和 references/orchestration.md，按编排单流程剪"。
- **写 edit.json 的推荐方式**：照 `examples/claude-vs-codex/make_edit.py`，用 Python 生成。`T("关键词")` 取说出那个词的时间，每个元素都卡在字上，比手写 JSON 准，也更容易做到每分钟 15–20 个动效。
- **不能看图的助手**：必须跑 `plan` 和 `direct`，交付时把 `stills/contact.jpg` 发给用户确认。
